# P1 New Core Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the P0 prototype port into the GDD v0.2 loop: 30 levels in 6 biomes with length reset and a 1 s transition, energy orbs and 4 skills, a 2-slot loadout, permanent checkpoints with energy carry-over, save v2 and a local run log, ending in a 5-tester playtest.

**Architecture:** Pure deterministic core (`src/core`, plain-data `SimState`, 1 ms fixed step, one explicit step list in `sim.ts`) extended mechanic by mechanic; pure meta (`src/meta`: save v2, progression, loadout sanitizing, run log) that never imports core; a new pure `src/session` that wires save + sim + run log; thin greybox Phaser scenes in `src/game`.

**Tech Stack:** TypeScript strict, Vite, Vitest (`node`), Phaser 3.90.0 (greybox only). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-03-p1-core-loop-design.md` (module layout, step order, session, scenes, tests, playtest, PR list) and the mechanic specs `docs/specs/mechanics/MEC-001-snake.md`, `MEC-002-mango.md`, `MEC-003-levels-biomes.md`, `MEC-006-energy-skills.md`, `MEC-007-loadout.md`, `MEC-008-checkpoints.md` (they win for every rule). Base: P0 design `docs/superpowers/specs/2026-11-03-p0-foundation-design.md` §3–§4.

**Precondition:** P0 exit criteria passed (P0 design §1; P0 plan `docs/superpowers/plans/2026-11-03-p0-foundation.md`, all 9 PRs merged, parity entry in `docs/PLAYTEST.md`). If not, stop and tell the lead. (At plan time the P0 plan file does not exist yet; this plan assumes the P0 design names below.)

## Global Constraints
- English only in every file (AGENTS §0). Conventional Commits. One task = one branch = one PR (AGENTS §6). Commit/push only when the human asks (AGENTS §8).
- `src/core` and `src/meta`: pure TypeScript. No Phaser, `window`, `document`, `localStorage`, `Math.random`, `performance`, `Date` (P0 boundary test).
- `src/meta` never imports `src/core`. Meta functions take plain config slices typed structurally in meta (`CheckpointsConfig`, `UnlockTable<Id>`); the core `Balance` groups satisfy them.
- `src/session` imports only `src/core/index.ts` and `src/meta/index.ts`; it never imports Phaser, `window`, `document`, `localStorage`, `Math.random`, `Date` or `performance`. Time (`now`) and seeds come in through `SessionDeps`. The P0 boundary test adds `src/session`.
- `src/game` imports `src/session` for everything run-related; it imports `src/core` only for types and pure HUD helpers (`quota`, `isChallenge`, …).
- Sim state is plain JSON-serializable data and `sim.clone()` exists (P0 design §3/§4). P1 adds no closures or class instances to the state.
- Obstacles are HazardFamily registry entries. Registry order: `rock, fence, maze, terrain, rottenRock, snipWall, rubble`. `rottenRock`, `snipWall`, `rubble` have no warn phase and `capClass: 'none'` (never director-spawned, excluded from the director cap).
- No magic numbers: every tuning value lives in `config/balance.json` and is validated by `parseBalance`.
- Determinism (P0 §4): same seed + balance + timed `turn`/`useSkill` calls ⇒ same state for any `advance` chunking. All gameplay randomness uses the core RNG.
- Test names start with the rule ID (`MEC-006-R21 …`); main implementing functions carry a one-line `// MEC-0xx-Rn` comment.
- `npm test` stays < 10 s; heavy fuzz only in `npm run test:fuzz` (`vitest run --mode fuzz`).
- Every PR: CHANGELOG `[Unreleased]` line; CODEMAP rows when modules change; `docs/README.md` row when a doc is added; STATUS rewritten at session end.
- Installing dependencies, pushing, and editing AGENTS.md / CLAUDE.md / `.claude/` / `.github/` need owner approval.

```ts
  return isChallenge(b, n) ? base + d.challengeCapBonus : base;
```

```ts
  if (!def) throw new Error(`skill ${id} lands in P1 PR 7`);
  if (s.phase === 'transition') return reject('busy');
  if (def.active(s)) return reject('active');
  const cost = b.skills[id].cost;
  if (s.energy < cost) return reject('energy');
  if (!def.precondition(s, b)) return reject('noTarget');
  const before = s.energy; s.energy -= cost;
  ctx.emit({ type: 'energyChanged', energy: s.energy, delta: -cost, source: 'skill' });
  ctx.emit({ type: 'skillUsed', slot, skill: id, level: s.level, energyBefore: before, energyAfter: s.energy });
  def.apply(s, b, ctx);
}
```
Slow-mo: `apply` sets `slowmo = {leftMs: durationMs}`; step 7 counts down and emits `skillEnded` at 0. `effectiveTick = slowmo ? Math.round(baseTickMs(s, b) * tickFactor) : baseTickMs(s, b)`; step 8: if it differs from `s.tickMs`, `s.acc = Math.min(s.acc, eff)`, `s.tickMs = eff`. Tail Snip: `K = Math.max(minLength, Math.ceil(L / 2))`; `removed = cutTail(s, K, minLength)`; drop the head's next cell (head + first queued dir, else `dir`); push one `SnipWall` (`wallLifeMs`) if any cell remains; emit `tailSnipped {cut: removed.length, cells}`.
