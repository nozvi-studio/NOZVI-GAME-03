# P3 UI fixes, Wave 1 (board occlusion + colour) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop in-run text from covering the board (banner strip, reject toast above the skill button, waiting prompt in the chip row) and make dark-theme text readable (>= 4.5:1) with a bright snake rim in biome 6 (>= 3:1), without touching gameplay.

**Architecture:** Every decision stays in pure modules and is unit-tested: `banners.ts` (`bannerStrip`, `clipLine`), `hudLayout.ts` (`bannerStripRect`, `stripRows`, `skillTipPlacement`), `hudModel.ts` (chip kind `wait`), `uiTokens.ts` (`uiTheme`), `biomePalette.ts` (`snakeRim`). Phaser views (`BannerLayer`, `HudTop`, `PauseOverlay`, `SettingsScene`, `drawSnake`) only draw what the models return. Queue, timing and motion of banners are unchanged.

**Tech Stack:** Phaser 3.90, TypeScript strict, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-07-p3-ui-review-fixes-design.md` (§2 rulings, §3 UIFIX-R1..R3, §4 UIFIX-R4..R5, §7 testing). Findings: `docs/PLAYTEST.md` "2026-11-07 - P3 UI review".

## Findings (spec ambiguities resolved)
1. **R3 "new text key".** `TEXT.waitHintKeys` ('Press an arrow to go!') already exists; only the touch string is new ('Swipe to steer!'). The prompt moves into the `t()` dictionary as `hud.wait.touch` / `hud.wait.keys`, and the old `TEXT.waitHintKeys/waitHintTouch` entries are removed (single source, no dead strings). The touch test is the existing `this.sys.game.device.input.touch` check, moved into a pure helper.
2. **R1 skill pills.** Pills are persistent state indicators that can coexist with a banner. They keep their own compact pill look but are moved to sit directly under the strip (flush with the board top edge + strip height + gap) so nothing overlaps; they are not queued.
3. **R1 level-up sub line.** The strip allows one sub line, so the "Your snake shrinks to N segments" chip text becomes the sub line when the snake shrank (it is the more informative line, MEC-001-R4), otherwise "Fresh start!".
4. **R1 biome / checkpoint.** Biome: title = biome name, sub = tagline (the "BIOME n" label is dropped). Checkpoint: title + "Checkpoint saved". Challenge and hint: title only. Titles and subs are cut to one line with `clipLine`.
5. **R2 toast.** `BannerLayer.tip(text, tailSlot)` already draws a bubble with a tail above a skill button (used by "New skill: X"). The reject toast reuses it with the rejected slot. Its placement moves into a pure `skillTipPlacement` that clamps the bubble top to the bottom edge of the board, so it can never cover the board. It may overlap the chip row for one toast (accepted).
6. **R4 scope.** Dark tokens apply where text is drawn directly on the dark game background (HUD level and biome titles) and to the Pause card and the Settings screen (background, cards, ink). Stat pills / chips / skill buttons keep their light cards with dark ink (already >= 4.5:1 and unchanged). "Dark" means the resolved theme (`themeOf(currentPalette())`), so it follows the saved setting or the OS.
7. **R5 rim colour.** Biome 6 (Storm Garden) only: `#7CF2D4` (the storm grid colour). Dark theme does not change biome 6 ground, so one value serves both themes; the test checks both themes anyway.
